# Архитектура «Легенд Эльдории»

Одностраничная 2D RPG без зависимостей и без рантайм-библиотек: всё рисуется на `<canvas>`, звук синтезируется, ресурсов-картинок в игре нет (кроме иконок PWA). Играть: https://kryukovmikhail.github.io/eldoria/

## Технический стек

| Слой | Что используется |
|---|---|
| Язык | JavaScript (ES2020, без транспиляции, без модулей/бандлеров), HTML5, CSS3 |
| Рендер | Canvas 2D (`getContext('2d')`), процедурная отрисовка: деревья, горы, вода, герой, враги, здания, погода рисуются кодом; тяжёлые слои (земля, подземелья, вода) кэшируются во внутренних canvas |
| Звук | Web Audio API (`AudioContext`/`webkitAudioContext`): SFX и музыка по уровням синтезируются осцилляторами/шумом, файлов нет |
| Ввод | клавиатура + мышь на десктопе; экранный джойстик и кнопки (в т.ч. «Рыбалка») на iOS/Android; Pointer/Touch events |
| Хранение | `localStorage`: слоты сохранений, настройки качества и звука, снимок героя для «Новой игры+» (`eldoria_ngp`); экспорт/импорт сохранений |
| PWA | `manifest.webmanifest` + `sw.js` (сеть-сначала, офлайн-кэш; имя кэша `eldoria-D001.0NN` синхронизируется сборкой) |
| Сборка | `tools/build.py` (Python 3, только стандартная библиотека) |
| Тесты | Python + Playwright (Chromium), `tests/t*.py`, запуск `tests/run_all.py` |
| CI/CD | GitHub Actions (`.github/workflows/ci.yml`), публикация — GitHub Pages из ветки `main` |

## Структура репозитория

```
src/index.template.html   разметка: меню, оверлеи (журнал, лавка, диалоги), метки /*@@CSS@@*/ и /*@@JS@@*/
src/style.css             стили, адаптив под мобильные
src/js/NN_*.js            код игры, ~8,3 тыс. строк в 25 файлах
tools/build.py            сборка src/ -> index.html (+ sw.js)
tests/                    автотесты; tests/hook.txt — тестовый хук
index.html, sw.js, ...    публикуемые файлы (index.html — собранный артефакт, хранится в git)
```

## Ключевые решения

- **Один файл на выходе.** `build.py` склеивает все `src/js/*.js` в алфавитном порядке внутри одной IIFE `(() => { ... })();`, CSS и JS подставляются в шаблон. Итог — единый `index.html` (~670 КБ), который работает и с `file://`.
- **Модули — это куски одного скрипта.** Нет `import/export`; функции поднимаются (hoisting), а `const/let` верхнего уровня безопасно использовать только в рантайме, не на этапе загрузки соседнего файла. Новый модуль называют так, чтобы он встал в нужное место (`92b_meta.js` стоит перед `93_…`).
- **Мир — граф локаций.** Уровни, логова боссов, подземелья, город, дома и арена — это `loc`-объекты в `world`; переходы между ними — двери/пещеры. Локации сохраняются целиком, поэтому всё, что лежит в `loc` (препятствия, ловушки, NPC, травы), переживает сохранение.
- **Процедурная графика + кэширование.** Статичные слои рисуются один раз во внутренний canvas, динамика — каждый кадр. Автокачество по FPS снижает частицы, тени и погоду на слабых телефонах.
- **Тесты через хук.** Игра живёт внутри замыкания, поэтому тестовая сборка (`--test` → `dist/test.html`) вставляет в конец скрипта содержимое `tests/hook.txt`, выставляющее `window.__t` (состояние и нужные функции). Playwright запускает эту страницу и проверяет механику, сохранения, отрисовку и производительность. Каждая новая функция, нужная тесту, добавляется в хук.
- **Сохранения.** Игрок сериализуется списком ключей (`PLAYER_KEYS`), локации — целиком. Поля, добавленные позже, подтягиваются при загрузке (`ensureWorldExtras`, `ensureMetaFields`), поэтому старые сохранения продолжают работать.

## Сборка, тесты, релиз

```bash
python3 tools/build.py          # index.html + sw.js
python3 tools/build.py --test   # dist/test.html с хуком
python3 tests/run_all.py        # все тесты (нужен playwright + chromium)
```

CI на каждый push: проверка синтаксиса модулей (`node --check`) → пересборка и проверка, что `index.html`/`sw.js` в git совпадают с `src/` → тестовая сборка → Playwright-тесты.

Релиз: поднять номер сборки в `src/index.template.html` (`#buildTag`), выполнить `python3 tools/build.py`, закоммитить `src/`, `index.html`, `sw.js`, запушить в `main` — GitHub Pages опубликует.

## Ограничения

- Нет серверной части: сохранения живут только в браузере (перенос — через экспорт/импорт).
- Весь код в одном скоупе: нет изоляции модулей и типов, согласованность держится на соглашениях и тестах.
- Тесты гоняются в десктопном Chromium; поведение на реальных iOS/Android проверяется вручную.
